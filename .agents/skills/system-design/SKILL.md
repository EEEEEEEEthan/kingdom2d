# Kingdom2D 系统设计

## 使用时机

- 与用户讨论玩法、系统、数值、流程
- 实现新功能前，确认是否已有设计约束
- 用户给出或确认一条设计规则时

## 工作流程

1. **先读**：按主题打开下方子文档，避免与已定设计冲突
2. **讨论**：未决问题标为「待定」，不擅自写成已定
3. **冲突**：发现任何设计冲突（新提议 vs 已定决策、子文档之间、设计 vs 代码现状）时，**必须立即向用户提出**，说明冲突双方，暂停写入或实现，待用户裁决
4. **记录**：用户明确确认后，写入对应子文档的「已定决策」
5. **idea**：用户提出但未确认的想法写入 [idea-pool.md](idea-pool.md)；采纳时迁入对应子文档并标为已定，弃用时标为「已弃用」
6. **联动**：若决策影响代码结构或命名，实现时同步遵守

## 记录格式

每条已定决策使用：

```markdown
### [简短标题]

- **状态**：已定
- **规则**：[一句话核心约束]
- **说明**：[展开、边界、未覆盖处]
- **开放问题**：（可选）
```

## 维护原则

- **idea 非约束**：idea 池内容不得当作已定决策引用或据此实现
- **冲突优先**：不得忽略、淡化或自行调和设计冲突；未获用户确认前，不得将冲突一方悄悄记为已定
- 子文档是设计真源；聊天里的口头约定未写入文档则视为未固化
- 修改已定决策时，在原文改为「已废止」，勿静默删除
- 保持简洁，只记对实现有约束力的内容
